Un hook es una garita en el camino.

Claude Code corre tu comando en un momento fijo de su ciclo de vida, siempre, sin depender de que el modelo decida hacerlo. Tu comando revisa lo que viene y decide si pasa.[1]

Anatomía de la garita

Tres niveles, una caja dentro de otra

Un hook vive en un archivo de configuración. Adentro hay un solo objeto hooks; cada evento es una llave; cada evento tiene grupos con un matcher; y cada grupo tiene los handlers que corren.[2]

Toca cada caja del diagrama. La línea correspondiente del JSON se enciende.

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/protect-files.sh",
            "timeout": 30
          }
        ]
      }
    ]
  }
}

¿La pluma se abre o se cierra?

Tu script le responde a Claude Code con su código de salida. El mismo exit 2 no hace lo mismo en todos los eventos. Elige un evento, mueve el código de salida y predice antes de mirar el resultado.[7]

Se detiene

Qué pasa
Tu mensaje
exit 0

no aprueba nada. En PreToolUse solo quiere decir "sin objeción": la herramienta sigue el flujo normal de permisos y Claude Code te pregunta igual si hace falta.[7]

Antes o después

La garita va antes o después de la herramienta

Los dos eventos ven la misma herramienta con el mismo matcher. La diferencia es de qué lado del camino está la garita.

PreToolUse

  • Ve lo que Claude va a hacer en tool_input, por ejemplo el comando de Bash.[8]
  • Puede bloquear con exit 2; tu stderr le llega a Claude como motivo.
  • Úsalo para: proteger archivos, rechazar comandos peligrosos.
# bloquea si el comando borra una tabla
COMMAND=$(jq -r '.tool_input.command')
if echo "$COMMAND" | grep -q "drop table"; then
  echo "Blocked: no se borran tablas" >&2
  exit 2
fi
exit 0

PostToolUse

  • Corre después de que la herramienta terminó bien; no puede deshacer la acción.[9]
  • Con exit 2 solo le muestra tu stderr a Claude.
  • Úsalo para: formatear lo que se editó, registrar comandos.
# formatea cada archivo que Claude edita
"matcher": "Edit|Write",
"command": "jq -r '.tool_input.file_path' | xargs npx prettier --write"

Ejemplo de la guía oficial; usa jq para leer el JSON de entrada.[10]

Quién atiende la garita

    
Cinco tipos de handler

    
El campo type decide quién toma la decisión. Para empezar, casi siempre vas a usar command.[5]

    

      

        
command

        
600 s por defecto

        
Corre un comando de shell. Habla con Claude Code solo por cuatro canales:

        
        
No puede ejecutar comandos / ni llamar herramientas.[9]

      

      

        
http

        
Manda el mismo JSON por POST a una URL y lee la respuesta.

      

      

        
mcp_tool

        
Llama una herramienta de un servidor MCP configurado.

      

      

        
prompt

        
30 s por defecto
Un modelo de Claude evalúa en una sola vuelta y responde {"ok": true} o {"ok": false, "reason": "..."}. Para decisiones que piden criterio.[12]

      

      

        
agent

        
60 s por defecto · experimental
Lanza un subagente que puede leer archivos y buscar en el código antes de decidir, por ejemplo correr las pruebas antes de dejar que Claude se detenga.[13]

      

    

  


  
  

    
La regla que no se olvida

    
Tu hook corre con todos tus permisos de usuario.

    

      
Un hook command puede modificar, borrar o leer cualquier archivo al que tu cuenta tenga acceso. Revisa y prueba cada comando antes de agregarlo a tu configuración, sobre todo si lo copiaste de otro lado.[14]

      
    
        
  • Entrecomilla las variables de shell: "$VAR", no $VAR.
    • 
        
  • Usa rutas absolutas, con "$CLAUDE_PROJECT_DIR" para los scripts del proyecto.
    • 
        
  • Revisa que las rutas no traigan .. y no toques .env, .git/ ni llaves.
    • 
        
  • Pruébalo a mano antes: echo '{"tool_name":"Bash","tool_input":{"command":"ls"}}' | ./mi-hook.sh; echo $?[15]
    • 
        
  • Un "deny" de un hook se mantiene en cualquier modo de permisos, incluso con bypassPermissions.[16]
