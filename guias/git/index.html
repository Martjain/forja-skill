Guía visual · nivel principiante

Cómo funciona git

Git guarda tu proyecto como un hilo de fotos. Cada foto es un commit, y las ramas son etiquetas que cuelgan de ese hilo y avanzan cuando agregas fotos nuevas.

3zonas por las que pasa un cambio [1]
40caracteres en cada hash SHA-1 [1]
41bytes ocupa una rama [3]

01 · La idea central

Git guarda fotos, no listas de cambios

La mayoría de los sistemas anteriores guardaban, para cada archivo, la lista de cambios que fue recibiendo. Git piensa distinto: cada vez que haces un commit, toma una foto de cómo están todos tus archivos en ese momento [1].

Otros sistemas: diferencias

Para ver la versión 3 de C, el sistema parte de C y le aplica Δ1 y luego Δ2.

Git: instantáneas

Cada versión es una foto completa. Si un archivo no cambió (punteado), Git no lo vuelve a guardar: deja un enlace a la copia idéntica que ya tenía [1].

Todo el historial vive en tu disco. Como cada copia de un repositorio trae la historia completa, casi todas las operaciones (ver el historial, comparar versiones) no necesitan red y se sienten instantáneas [1].

02 · El mapa

Tres zonas en tu computadora y una en el servidor

Un proyecto con git tiene tres secciones: el directorio de trabajo, el área de preparación y el directorio de git [1]. Un cambio viaja de una a otra con un comando.

Por eso un archivo puede estar en tres estados: modificado (lo cambiaste pero no lo has confirmado), preparado (lo marcaste para el próximo commit) y confirmado (ya está guardado en la base de datos local) [1].

Toca cada zona del diagrama para ver qué vive ahí y con qué comando entra o sale un cambio.

03 · Manos en la terminal

Tu primer repositorio, paso a paso

Vamos a seguir un solo archivo, receta.txt, desde que nace hasta su segundo commit. Las salidas son las que imprime git 2.43; los hashes cambian en tu máquina.

    
          
    
            
            
            
    Paso 1 de 6
    
          
    
        
    
      
    
    
    
    
    
      
    Antes del primer commit, dile a git quién eres. Cada commit guarda este nombre y correo, y no se pueden cambiar después sin reescribir el commit [8]. Con --global lo haces una sola vez por computadora.
    
      
    $ git config --global user.name "Ana López"
$ git config --global user.email ana@ejemplo.com
$ git config --global init.defaultBranch main
    
    
    
  
    

  
  
    
    
    
      
    
        
    04 · La huella
    
        
    40
    
        
    caracteres hexadecimales identifican cada cosa que git guarda
    
        
    Es el hash SHA-1: una huella de 40 caracteres (0 a 9 y a a f) calculada a partir del contenido [1]. Git guarda todo en su base de datos por el hash de su contenido, no por el nombre del archivo, así que no puedes cambiar un archivo sin que git lo note [1].
    
      
    
      
    
        
    Para un archivo, git antepone un encabezado (blob, un espacio, el tamaño en bytes y un byte nulo) y calcula el SHA-1 de todo junto [10]. Este probador hace exactamente eso en tu navegador. El texto inicial es el ejemplo del libro oficial; su hash debe dar bd9dbf5a… [10].
    
        
    
          
          
          
    
          
    
          
    
          
    
          
    Compruébalo en tu terminal: echo -n "what is up, doc?" | git hash-object --stdin
    
        
    
        
    Cambia una sola letra: casi todos los caracteres del hash cambian. Por eso dos contenidos distintos nunca comparten huella en la práctica, y un archivo idéntico siempre da el mismo hash.
    
      
    
    
    
  
    

  
  
    
    
    05 · Ramas
    
    
    Una rama es solo una etiqueta que se mueve
    
    
    Cada commit guarda un apuntador a su foto, el autor, el mensaje y un apuntador al commit anterior (su padre) [3]. Así se forma el hilo. Una rama no copia archivos: es un apuntador ligero y movible a uno de esos commits [3].
    
    
    
      
    
        
    El hilo, las etiquetas y HEAD
    
        
        
    Recién creaste idea: las dos etiquetas están sobre el mismo commit. HEAD es un apuntador especial que indica en qué rama local estás parado [3]. Cuando haces commit, la rama a la que apunta HEAD avanza sola al commit nuevo [3].
    
      
    
      
    
        
    41
    
        
    bytes: eso cuesta crear una rama. Es un archivo con los 40 caracteres del hash del commit y un salto de línea [3].
    
      
    
      
    
        
    git branch idea
    
        
    Crea la etiqueta en el commit actual, pero no te cambia a ella [3].
    
      
    
      
    
        
    
          
    git switch idea
    
          
    Mueve HEAD a idea. Desde git 2.23 existe switch; git switch -c idea crea la rama y te cambia en un solo paso. El comando anterior, git checkout, sigue funcionando [3].
    
        
    
        
    $ git log --oneline --decorate
f30ab (HEAD -> main, idea) Add feature #32
34ac2 Fix bug #1328
98ca9 Initial commit
    
      
    
    
    
  
    

  
  
    
    
    
      
    06 · Laboratorio
    
      
    ¿Qué pasa cuando fusionas una rama?
    
      
    Trabajaste en idea y ahora corres git switch main y git merge idea. El resultado depende de una sola pregunta: ¿alguien agregó commits a main mientras tanto? Mueve los controles y predice antes de mirar.
    
    
    
    
    
      
    
        
      
    
      
    
        
    
          
          0
          
          
    0123
    
        
    
        
    
          
          2
          
          
    123
    
        
    
        
    
          Las dos ramas cambiaron…
          
          
    
        
    
      
    
      
    
        
    
          
          
    
        
    
        
    
      
    
    
    
    
    El 0 está marcado: es el punto crítico. Con 0 commits nuevos en main hay fast-forward [4]; desde 1 en adelante, git necesita una fusión de tres vías con un commit de fusión de dos padres [4].
    
  
    

  
  
    
    
    07 · Compartir
    
    
    Cuatro comandos para trabajar con un remoto
    
    
    Un repositorio remoto es otra copia de tu proyecto, alojada en internet o en una red [6]. Tu copia local guarda un marcador, origin/main, de dónde estaba la rama main del remoto la última vez que hablaste con él [5].
    
    
    
      
      
    1. 
        
      git clone <url>
      
        
      Trae una copia completa: cada versión de cada archivo de toda la historia [9]. Git llama origin al remoto, crea el marcador origin/main y te da tu propia rama main en el mismo punto [5].
      
      
      2. 
      
    2. 
        
      git fetch
      
        
      Pregunta al remoto qué tiene que tú no, lo descarga a tu base de datos local y mueve origin/main [5]. Solo descarga: no mezcla nada con tu trabajo [6].
      
      
      3. 
      
    3. 
        
      git pull
      
        
      Corre git fetch y después integra la rama remota en la rama en la que estás [7]. Si las dos historias se separaron, git te pide elegir cómo integrarlas (fusión o rebase) [7].
      
      
      4. 
      
    4. 
        
      git push origin main
      
        
      Calcula qué tiene tu base de datos que el remoto no y se lo envía; necesita permiso de escritura [11]. Si alguien empujó antes que tú, te lo rechaza: primero trae su trabajo, intégralo y vuelve a empujar [6].
      
        
      $ git push origin main
 ! [rejected]        main -> main (fetch first)
$ git pull
$ git push origin main
