Hooks de Claude Code tu script en el cable

Un hook es un comando tuyo que Claude Code ejecuta solo cuando pasa algo: antes de usar una herramienta, después de editar un archivo, al terminar de responder. No depende de que el modelo se acuerde.[1]

01 · Qué es

Siempre, no casi siempre

Un hook convierte una petición al modelo en algo que pasa cada vez que ocurre el evento.

determi­nista

Así describe la documentación el control que dan los hooks: ciertas acciones siempre ocurren, en vez de depender de que el modelo decida hacerlas.[1]

Un hook es un comando de shell que tú defines. Claude Code lo corre en puntos fijos de su ciclo de vida.[1]

Si escribes en CLAUDE.md «formatea después de editar», Claude casi siempre lo hace. Con un hook, se hace siempre.

  • Formatear cada archivo editadoPostToolUse
  • Impedir ediciones a .envPreToolUse
  • Avisarte cuando Claude esperaNotification
  • Recordar contexto tras compactarSessionStart

    07 · Cuando no funciona
    
      
    Cinco fallas de principiante
    
      
    Casi todo hook que «no hace nada» cae en una de estas cinco. Todas vienen de la sección de problemas de la guía oficial.[1]
    
      
      
        
    1. 01
      
          
      El script nunca corre
      
          
      En macOS y Linux el script debe ser ejecutable. Si ves «command not found», usa una ruta absoluta o "$CLAUDE_PROJECT_DIR".
      
          
      chmod +x .claude/hooks/protect-files.sh
      
        
      2. 
        
    2. 02
      
          
      El matcher no coincide
      
          
      Distingue mayúsculas: bash no dispara con la herramienta Bash. Revisa también que el evento sea el correcto: PreToolUse va antes, PostToolUse después.
      
        
      3. 
        
    3. 03
      
          
      Tu JSON se ignora sin dar error
      
          
      Dos causas: algo imprime antes de tu { (un echo en ~/.bashrc), o un campo quedó en el nivel equivocado, como permissionDecision fuera de hookSpecificOutput. Arranca con claude --debug y busca el aviso en el registro.
      
        
      4. 
        
    4. 04
      
          
      Stop no deja de bloquear
      
          
      Si tu hook de Stop siempre sale con exit 2, Claude nunca termina. Claude Code lo anula tras 8 bloqueos seguidos, pero lo correcto es revisar stop_hook_active y salir con 0 si ya es true.
      
          
      if [ "$(jq -r '.stop_hook_active' <<<"$INPUT")" = "true" ]; then exit 0; fi
      
        
      5. 
        
    5. 05
      
          
      No sabes si corrió
      
          
      Un hook exitoso no muestra nada. Pruébalo a mano: pásale un JSON de ejemplo por stdin y mira su código de salida. Dentro de Claude Code, Ctrl+O abre la transcripción y /debug activa el registro.
      
          
          
      echo '{"tool_name":"Bash","tool_input":{"command":"ls"}}' | ./mi-hook.sh
echo $?
